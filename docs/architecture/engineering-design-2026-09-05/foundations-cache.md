# Foundations / RuleSet cache implementation design

Design input: canonical engineering-audit-2026-09-05/foundations.md FND-01–05 and runtime-dns.md RD-02/03/08, current config/rule/ruleset scoped AGENTS, and current source/cache/loader/blocking/snapshot/refresh/download implementations. This is a selected design, not implementation or verification. No product files, paused SRS work, tests, compiler, benchmarks or dynamic reproductions were touched. The codebase-design skill informed the module/interface/seam choices.

## Selected architecture

Keep three deep modules with independent owners: a side-effect-free admitted egress graph in config; strict bounded SRS decoding in rule; a RuleSet-specific cache transaction/work owner in ruleset. The loader remains the network/composition orchestrator. Do not introduce a workspace-wide executor, make config depend on ruleset/runtime, or make rule perform filesystem/network work. Keep MaterializedRuleSets as the sole initial-to-refresh identity handoff.

### 1. Configuration graph admission and one derived plan

Add a private config validation owner, validation/egress_graph.rs, for the complete egress identity/member/chain topology. Its interface takes named client/server graph input, validates structural bounds before allocating graph-proportional derived state, and returns AdmittedEgressGraph. Fields are private; invalid graphs cannot enter capability calculation. prepare/core remains the phase orchestrator and consumes focused results rather than forwarding a vocabulary/prelude.

Admission order:
1. Existing bounded source/UTF8/version/Serde parsing.
2. Count/tag identity checks before ClientPreparationDraft::new / prepare_dns / capability evaluation. Count ordinary inbounds plus the optional TUN identity without inserting a placeholder listener first. Admit each configured inbound/outbound/selector/chain cohort to existing 64 limits, selectors to existing 64 immediate members, chains to existing 2–8 hops. Validate both roles' forbidden cohorts here, including server chains. DNS listeners/servers retain 64 limits. RuleSet declarations receive an explicit 64-resource ceiling, checked here and again in public ruleset materialization (see resource policy below).
3. Resolve every egress reference once into typed OutboundId/SelectorId/ChainId indices, reject duplicate identities/members/hops and invalid defaults, reject Direct chain hops per current client contract. Use iterative DFS or Kahn ordering to reject all cycles; retain closed node/index cycle evidence.
4. Build graph derivations in dependency-first order. Each node owns a first-hop bitset of at most 64 bits and a domain-target capability. Outbound first hops are its bit; a chain uses its first outbound, capability from its permitted terminal outbound; a selector unions immediate members' first-hop sets and ANDs domain capabilities. Shared successors are computed once. Complexity O(V+E), retained summaries O(V), no root-to-leaf path materialization.
5. DependencyGraphInput consumes this admitted typed topology plus already bound outbound endpoint/Direct resolver and DNS/RuleSet dependencies. It remains distinct from the egress-only topology: resolver dependency cycles and egress selection cycles have different semantics. DependencyGraphPlan carries named order/reached DNS results, not parallel positional slices.
6. Route action roots resolve to typed graph references. Derive physical first hops and direct-detour status from bitsets, preserving sorted concrete outbound order, then construct core's existing immutable plans/selectors. Core keeps independent public input validation as defense of its public interface; config's early admission is not permission to weaken core. Core reachability checks still include all route, DNS detour and RuleSet detour roots.

Selected public change: none required for initial config graph repair; the new types are private. Replace the recursive EgressCapabilityEvaluator and client first_hops string/pending traversal; remove redundant string re-resolution once typed graph consumers land. Preserve Client/ServerPreparationDraft binding of raw outbound→endpoint→Direct resolver exactly once. Do not retain the old evaluator as a fallback or a compatibility path. Existing placeholder-sanitization removal is desirable only where this admitted graph directly replaces its role; do not widen this patch into all config preparation.

Alternative: retain current graph and add a visited bitset per root plus an early count pass. This is smaller but retains two separate graph interpretations/cycle algorithms and repeated tag lookups; acceptable only as an interim implementation step inside one reviewable transition, not the final architecture. Alternative: a generic graph framework adds vocabulary and trait obligations without a second real topology algorithm consumer; reject it.

### 2. Listener alias checks

Add a private ListenerIdentitySet/validate_listener_set in validation/common or a cohesive validation/listener owner. Its input is typed declared listener role/index/address/transport coverage; errors retain the conflicting field, not address text. Both client and server ordinary listeners and metrics use the same same-family overlap predicate already used by DNS: same port and either equal IP or either wildcard. Account for TCP-only metrics versus TCP+UDP DNS/listener transport coverage rather than rejecting disjoint transports accidentally.

Do not mix TUN pseudo-inbound 0.0.0.0:0 into actual listener identities. Run declared listener checks during prepare; rerun relevant outbound/DNS target-loop checks after resource materialization using the same address relation. Preserve current endpoint collision policy rather than adding speculative restrictions on arbitrary remote targets. IPv4/IPv6 dual-stack alias policy must match actual socket IPV6_V6ONLY settings from the owning binaries; same-family fix can land without claiming cross-family portability. No socket binding belongs in config.

Remove ordinary listens.contains equality-only rejection and metrics proxy_listens.contains. Preserve deterministic field-specific errors and loopback-only metrics.

### 3. One strict SRS limits interface

In ferrum2-rule::srs add a private-field SrsDecodeLimits with a reviewed default and a validated constructor for explicitly tighter limits. Public decoder becomes decode_srs(reader, limits); update every repository caller at once, including qualification, fuzz/test helpers and ruleset cache. No unlimited overload/default compatibility alias remains. A named SrsLimitKind (EncodedBytes, DecodedBytes, Rules, Entries, Collection, DomainDepth, ExpandedBytes, KeywordBytes, Work) can accompany SrsErrorKind::LimitExceeded through closed error mapping. Errors never carry input values.

Implementation owner is DecodeContext, holding reader counters plus monotonically consumed work/retained-entry/string allowances. Every primitive receives that context rather than independent optional limits. Limits count attempted decoded items before dedup, so repeated values cannot bypass work bounds. Logical nodes share the file rule/work budget and retain maximum depth 100. Unsupported fields remain fully validated within these same budgets before the current unsupported classification; skip irrelevant strings via a bounded scratch reader instead of allocating values solely to discard them.

Reader layering must prevent read-ahead bypass: a bounded encoded reader sits beneath BufReader and StrictZlibDecoder; a bounded decoded reader sits immediately above the decoder and beneath parser buffering. Reaching the bound is not ordinary EOF: allow an independently bounded one-byte EOF probe and return LimitExceeded if present. The strict zlib StreamEnd/trailing-payload/trailing-file contracts remain intact. Keep arithmetic overflow distinct from declared-but-over-policy limits.

Primitives validate declared length/count and checked minimum representation against remaining budget before reserve/resize. Reserve conservatively and grow with bytes/items actually read; do not allocate the entire claimed collection before its first element is known. In particular, a truncated declared string must not force a length-sized zero-filled allocation. This does not require retaining the whole decompressed file.

Domain succinct decoding keeps validated LOUDS words/labels and iterative frames, but sends each recovered key directly to the domain collector; remove the intermediate Vec<Vec<u8>> of all recovered keys. Bound frame depth before push and cumulative emitted bytes before copying. Domain wire depth accounts for the supported marker, optional leading dot and optional trailing dot; normalize once and validate the final 1–255 ASCII representation. Validate parent/child progress, bitmap/label accounting and terminal reachability to make O(nodes + emitted bytes) work explicit. Unsupported AdGuard succinct sets use the same bounded structural reader, without building supported domain storage.

IP range decomposition keeps ordering/canonicality checks, charges every emitted CIDR against entry/work allowance, and determines whether the current block covers the inclusive end before calculating a successor. A V6 final block ending at u128::MAX is successful termination; /0 retains its explicit no-shift-by-128 case. No saturating address arithmetic may silently merge or omit ranges.

### 4. Resource policy and evidence basis

Select fixed reviewed product defaults, with smaller injectable limits for ordinary contract tests. Do not add a large matrix of user tunables in TOML in the first implementation. Config owns syntax/structural counts; rule owns decoder expansion; ruleset owns network/cache/work concurrency. Types are transferred where needed, not duplicated as unrelated constants in callers.

Initial implementation envelope to adopt, subject to explicit fixture census at the later permitted verification phase:

| Resource | Default | Basis and remaining evidence |
|---|---:|---|
| Remote/cache encoded SRS | 64 MiB | Largest pinned file is ads.srs 782,961 bytes; ample headroom while bounding per-resource disk/read volume. This is an engineering ceiling, not a protocol maximum. |
| Decoded SRS bytes | 128 MiB | Independent compressed-output bound; avoids relying on compression ratio. Actual pinned decoded totals are not measured in this design. |
| Attempted logical/default nodes | 100,000 | Includes nested nodes, bounded by work even when unsupported or empty. Existing logical depth 100 retained. |
| Emitted matcher entries before dedup | 1,000,000 per file | Reviewed cn fixture has 110,866 suffix entries plus 6 exact; allows explicit 100k qualification scale with headroom. |
| Succinct nodes/labels | 8,000,000 | Caps frame/select/rank allocation and traversal independently of compressed bytes; must be checked against pinned/generated fixture census before final adoption of defaults. |
| Expanded domain/keyword bytes | 64 MiB per file | Bounds copies and sorting input, independent of compact trie size. |
| Supported keyword string | 255 bytes | Target canonical domains are at most 255 ASCII bytes; longer substrings cannot match any target. No old long-keyword compatibility path. |
| Total supported keyword bytes | 1 MiB per file | Controls automaton input separately from million-domain sets. Pin a bounded automaton representation or explicitly verify its worst-case construction envelope; do not call a post-build check a pre-allocation bound. |
| Unsupported string payload | 8 KiB per string, under decoded/work cap | Only needs strict classification, no retained payload. Larger unsupported input is a closed limit error. |
| Metadata | 64 KiB serialized | Read with size check plus bounded reader before Serde; accommodates max URL plus bounded validators. |
| URL / ETag / Last-Modified | 8 KiB / 1 KiB / 128 bytes | URL matches config's existing ceiling; validator limits are new deliberate policy. Validate injected downloader responses and cached values, not only HTTP implementation. |
| Concurrent RuleSet operations | 2 per loader | Preserve existing intended real-work limit; includes workers whose callers cancelled. |
| Body handoff | two 32 KiB chunks per operation | Preserve streaming/backpressure; worker buffers plus producer buffer are explicit bounded overhead. |
| Initial declaration cohort | 64 resources | Matches other config resource cohorts and prevents unbounded independent cache/refresh owners. |
| Materialized snapshot contents | 2,000,000 total entries; 128 MiB expanded bytes; 2 MiB keyword bytes | A distinct registry-wide bound prevents 64 individually maximal files multiplying compiler/index work. Existing four pinned sets fit by published entry counts, but byte census remains required. |

These are application resource admission bounds, not a claim of exact RSS. Compiled index/automaton representations and sort temporaries require a documented structural upper estimate and later allocation census; preserve fallible allocation errors. In particular, choose a non-DFA keyword representation or an actual library-supported construction limit before claiming bounded automaton memory; the precise pinned aho-corasick interface must be confirmed from its source during implementation. No guessed builder method is prescribed here. Snapshot byte/entry totals must be available in CompiledMatchSet statistics so they are enforced before RuleEngineSnapshotBuilder allocates duplicate indexes. Existing arbitrary public Arc snapshots can retain old generations; this design bounds each admitted snapshot and ongoing work, not externally retained unlimited historical Arcs.

Limits are rejected before expensive work. A low-cap deterministic test interface uses the same limits object and decoder; it does not require any large or resource-exhaustion input. No such tests run in this design phase. Values above are selected defaults with transparent basis; unknown census rows are an implementation verification obligation, not fabricated compatibility evidence. If a reviewed fixture exceeds a default, revisit the policy explicitly rather than adding an unbounded exception.

### 5. Single-file cache generation

Choose one atomically replaced cache container per RuleSetCacheName, e.g. <name>.frs-cache. It contains fixed 64-byte header, raw compressed SRS payload, and bounded JSON metadata. Header has magic, closed schema version, payload length, metadata length, exact reserved-zero fields and metadata digest. Metadata retains normalized URL, validators, payload SHA-256, downloaded time, SRS version, exact capabilities and source generation. Define byte order/offsets once in cache/format.rs. Total file size must equal header + declared payload + metadata and stay below 64 + encoded limit + metadata limit. Reject unknown schema, nonzero reserved bits, duplicate metadata fields, invalid hex digest, excessive string lengths and tails before publication.

On download the worker creates a NamedTempFile in the destination directory, writes placeholder header, streams bounded payload directly behind it, then decodes/compiles through a payload-limited view of that same held file. Metadata is appended only after successful decode/compile/capability compatibility checks. Fill header, flush and sync file, then atomically replace the single cache path. Readers open once and validate one held file; they never reopen payload by path after hash verification. Replacing the name cannot mix metadata and payload generations. The cache container is not a new local-source configuration mode.

Use the existing tempfile dependency's same-directory persist/replace operation, after reviewing its pinned implementation for Windows and Unix atomic replacement guarantees. Do not emulate replacement as delete-destination then rename. If Windows sharing rules reject replacement while another reader holds the old file, preserve old file and return a closed cache-write error; opening share-delete where supported may improve availability but is not permission to add platform dependencies to ruleset. Unix syncs parent directory after replace. Windows's current no-op directory sync cannot substantiate power-loss persistence: promise atomic namespace replacement/process-crash consistency within supported filesystem behavior, distinguish durability uncertainty, and do not claim immunity to filesystem/hardware failure.

Serialize cache directory ownership with an exclusive loader-lifetime advisory file lock acquired by the cache worker, not a tag-based unbounded mutex map. Loader clones share the same cache owner; another live loader/process targeting the same directory receives a closed CacheBusy result instead of racing. Prefer std file locking supported by the pinned toolchain after source verification; do not introduce unreviewed native FFI. The lock file is owned by the module and contains no credentials; unlock only after all cache jobs are joined. This deliberately coarser policy avoids cross-process same-tag lost updates and bounded-key bookkeeping. It changes concurrent multi-loader cache-dir usage into a rejected contract; document it and update tests. Multiple processes may use separate cache directories.

Inside that exclusive directory, retain one FIFO async admission/serialization gate per loader for modifying operations (or two workers with a fixed bounded operation queue but serial commits). The worker owns the gate/permit through cancellation and final cleanup. No caller can free a commit slot while its prior write is still running. Reads and updates serialize with commits where needed; ordinary materialization/refresh already runs sequentially, so this avoids introducing speculative parallel cache semantics.

Remove schema-v1 .srs/.meta reader, separate two-file commit, path-only compile_file and srs/meta fallback. Old cache files are not migrated or trusted; normal remote fetch creates the current container. Do not proactively delete old/unrelated files during startup. Documentation must state old cache cannot serve offline startup after upgrade, consistent with no backward compatibility. Initial materialization still may populate individually valid cache resources without exposing a partial in-memory registry.

Alternative: immutable digest-named payload files plus one atomically replaced index. It avoids container metadata rewrites, but needs garbage collection, reader/reference coordination, orphan crash recovery and a total disk retention policy; reject for this bounded local cache. Alternative: two files plus rollback journal requires recovery for every failure gap and is not as deep/simple. Alternative: read entire download into memory then run one blocking transaction makes ownership easy but spends up to the encoded cap per operation and loses disk streaming/backpressure; reject.

### 6. Work lifecycle — owner stays with real work, not async waiter

Replace BlockingTaskOwner's externally used generic run closures with a private RuleSetCacheWork owner and typed operations: ReadCurrent, BeginDownload, BuildSnapshot, Shutdown. Keep its existing sticky failure/retryable join behavior, but all filesystem work (directory/lock acquisition, temp creation, chunk write, seek, hash, decode/compile, metadata write, sync, replace, temp removal) must execute inside explicitly registered blocking work. No tokio::fs operation or async-owned NamedTempFile remains. Do not return raw paths/Files/temp ownership to loader.

Loader load admission creates an owned operation task registered under the loader before it can poll the downloader. The operation holds cloned source/config, cancellation/deadline state, body and worker transaction. A public load caller only awaits an operation result; dropping that waiter signals cancellation but does not destroy the owner or release its actual-work permit. The operation task ensures body/detour transport ownership is closed/joined according to downloader's existing contract, then awaits worker cleanup, records sticky task/cleanup failure and releases admission. Downloader-created transport owners remain downloader/composition responsibilities with explicit shutdown ordering; the cache worker is not a network executor.

For streaming download, a dedicated blocking closure owns the temp file and a capacity-two 32KiB typed chunk receiver. The async operation reads body under the same absolute request deadline, checks encoded total before handoff, and sends bounded owned chunks; blocked send supplies backpressure. EOF is an explicit Finish message, never inferred from sender Drop. Sender Drop or cancellation means abort/remove temp. Worker recv must be stop-aware (bounded recv_timeout/control polling or a wait primitive that observes stop), not an uninterruptible await of a reply held behind shutdown. Worker reports Ready/Finished via one-shot results without awaiting caller acknowledgements. Closing the last producer releases receive; owner shutdown separately signals cancellation so it does not depend on waiter destruction.

The worker checks stop/deadline before each chunk, decode read/work checkpoint and before the commit gate. Pending OS write/sync/rename cannot be guaranteed interruptible. Cancellation returns no successful cleanup result until that work is joined; an outer caller may stop waiting, but loader.shutdown remains pending/retryable and retains handles/permits. Do not advertise a hard shutdown timeout for an uninterruptible OS call. After the atomic replace commit point, cleanup/cancellation must not delete the newly committed file or roll back by pathname.

Admission waiting must not hold directory locks or operation-state mutexes while waiting for a worker slot. Shutdown closes admission, cancels all async operations and stops chunk receivers, joins operations and workers while retaining handles across a cancelled shutdown future, then unlocks the directory. Join order must not hold a worker-needed mutex or retain a Finish/response capability behind its own join. Final result is sticky task/cleanup failure after every owner is reaped, not early exit on the first error. Ordinary Rust Drop must not silently declare complete cleanup; lifecycle callers must keep an explicit shutdown owner. Existing composition already calls loader/refresh shutdown and must retain that handle until completion.

BuildSnapshot is RuleSet-specific: execute initial/refresh registry index construction as tracked blocking work with the admitted aggregate limits; do not leave size-dependent builder.build in an async frame. It receives typed match-set/source identity input and returns one complete unpublished snapshot. No generic benchmark/executor trait is introduced.

### 7. Disk and live publication semantics

Maintain the existing independent cache and registry domains, with explicit commit points. Candidate decode/compile and expected capability check must finish before any cache replacement. Refresh calls are serialized by the refresh owner so generation reservation, complete successor construction and registry publication cannot race another refresh_once. Build the full successor before committing the candidate cache, then publish only that complete successor. Initial build remains all-or-nothing to callers, even if earlier resources have independently committed valid cache entries.

There is no atomic transaction spanning a filesystem rename and an in-memory Arc publication. Specify that cancellation/crash after cache replacement may leave a complete newer cache while current process still uses its complete older snapshot; never a mixed cache pair or partial registry. A registry publication failure keeps the current Arc unchanged; a complete compatible cache candidate may already exist. Do not claim every possible later failure preserves identical disk bytes. The RD-08 guarantee is old-or-new complete cache readability and no destruction of the only valid cache by an intermediate metadata failure.

For stronger 'failed refresh must leave both disk and live generation old' semantics, a two-phase publication/recovery journal would be required and cannot be made truly atomic across process memory and disk. Reject that expansion unless the product explicitly needs it. Preserve stable source tags/IDs/URL bindings inside MaterializedRuleSets; never substitute cache source generation for registry publication generation.

Network/limit/compile/cache write failure before commit uses verified old cache according to current OfflineCache/StaleCache semantics, with the original closed degraded reason. Corrupt/over-limit cache never becomes fallback evidence. 304 requires a previously fully verified current container; it does not waive resource/capability validation or establish a partial cache.

## Interfaces and planned change ownership

- config: private admitted graph + listener identity checking; update raw/prepare/model/validation only for the explicit declaration cap and typed graph handoff. No filesystem/cache module dependency.
- rule: SrsDecodeLimits/closed limit category, DecodeContext, bounded primitives/LOUDS collector/IP end handling, compiled entry/byte statistics sufficient for registry admission. All public callers updated atomically.
- ruleset source/download: validated operational limits and bounded URL/validator contract; Content-Length, if exposed by downloader, is an early rejection hint only. Streaming byte count remains authoritative for absent/false lengths.
- ruleset cache: private format/transaction subowners behind one held-file container contract; no legacy pair reader.
- ruleset loader/blocking: typed work lifecycle and owned streaming operation; no tokio-internal untracked fs work.
- ruleset snapshot/refresh: aggregate admission, owned snapshot build, serial refresh publication, same MaterializedRuleSets identity owner and explicit shutdown.
- composition and qualification consumers: replace decoder call signatures and closed error mappings; preserve immutable detour and one HTTPS deadline. Qualification tooling policy redesign remains root-owned.

## Later verification obligations, not executed here

Use ordinary small inputs and injected operation results through the same interfaces to establish graph work proportionality, early structure rejection, listener alias fields, each independent low injected decoder cap, maximum-address IPv6 termination and exact original fixture behavior. Cache filesystem operations need a private adapter with real std implementation and deterministic in-memory/scripted outcomes so failures/cancellation at each durable step are observable without inducing an OS stall. Confirm temp lifetime, producer close/worker stop, same-directory busy behavior, old/new container readback, unsupported metadata, failed compile/capability preservation, and retryable shutdown after waiter cancellation. This design does not authorize retrying prior blocked dynamic reproductions.

Run affected format/lint/test gates only in the later authorized implementation phase; qualification Rust remains compile-only in ordinary gates. Before adopting default limits, record reviewed fixture encoded/decoded/node/expanded-entry/keyword totals and compiler construction estimates. After functional gates pass, perform separately authorized paired qualification against retained baseline and then fast CPU profiling. No runtime, memory or throughput claim is established by this static design.
