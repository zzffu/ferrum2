# Rule tooling static engineering audit

Scope: tools/ferrum2-rule-qualification and tools/performance_rule. All production Rust/Python source files were individually read, plus the Rust match_set/tests.rs owner and sampled offline controller tests. Coverage is in rule-tooling-coverage.json. Root AGENTS.md, tools/AGENTS.md, both package AGENTS.md, package manifest and README, and tests/performance_rule/AGENTS.md were read. No code changes, benchmark workloads, generated abnormal inputs, test execution or dynamic reproduction were performed in this task.

## Confirmed source-level findings

### RTL-01 — P1 evidence integrity: raw runner evidence is not reconciled with the reported verdict
Location: tools/performance_rule/runner_report.py:130.
validate_report enforces exact field sets, positive finite metrics, sample-array lengths, minimum wall-clock batches and selected top-level true flags. It does not recompute ns/op from duration/operations, nearest-rank p50/p99 from samples, per-op allocation aggregates from allocation samples, or parity deltas/gates from the paired rows. allocation_gate_applicable is also trusted rather than derived from suite; individual correctness and parity-observation contents are not semantically checked. Thus mutually inconsistent current-schema evidence can reach summarize and review_calibration_source, which recompute only outer reductions of the accepted row summaries. The runner executable SHA binds the binary, not the mathematical consistency of retained evidence.
Impact: a producer regression or edited evidence file can be reviewed/reduced into an apparently valid calibration or comparison despite contradictory raw evidence. This is established by missing checks and dataflow, not a dynamically exercised forged artifact or a demonstrated malicious source.
Direction: define one current runner evidence validator that reconstructs all derived numbers and verdicts with a documented float tolerance; validate five single-op regions, suite gate scope, paired counterpart identity, selected mode and actual configuration/sample counts. Offline synthetic consistency tests can verify this without executing any runner.

### RTL-02 — P1 evidence comparability: equal scenario ids do not bind equal workloads/environment
Location: tools/performance_rule/runner_report.py:293; evidence.py load_calibration.
Across the twelve process reports the controller compares only id-to-suite maps. It does not require matching fixture hashes/byte counts, scenario metadata/scale, reported configuration, measurement policy or relevant environment characteristics. Calibration binds parent runner SHA, command arguments, execution priority and scenario map, but not consumed fixture content. workspace-root may therefore denote different fixture bytes over time while remaining the same argument; generated rows/real fixture scenario labels can remain unchanged. Each runner records fixture hashes, but these hashes are not used for comparability rejection.
Impact: cross-process/cross-version median reductions and reviewed calibration can compare changed workloads or environments and produce an adoption decision. No changed fixture was created or tested.
Direction: define a workload identity manifest from the exact consumed fixture bytes, configuration, scenario metadata and execution measurement policy; compare it across roles/pairs/calibration, separating intentionally differing runner identity. Define which host properties must match for calibration applicability. Tests should reject a single changed bound field with mocked reports.

### RTL-03 — P2: invalid supplied calibration is validated after runner execution
Locations: tools/performance_rule/cli.py:161; tools/performance_rule/cli.py:207.
A/B without a calibration stops before execution. A supplied file is checked only for current schema before the pair loop. Full approval/source hash/parent hash/arguments/priority binding is deferred until after all six pairs. Therefore a malformed or inapplicable artifact with the right schema still triggers the expensive qualification collection, then fails validation. This falls short of the README statement that A/B stops before runner execution without a reviewed current-schema calibration.
Direction: prevalidate approval, source report, hashes, arguments and execution policy, and derive the expected scenario/workload catalog before the first runner. Check each observed catalog against it during collection. A mocked-runner test should assert zero invocations for each failed precondition.

### RTL-04 — P2: generated synthetic-SRS build evidence is discarded and replaced by binary build evidence
Locations: tools/ferrum2-rule-qualification/src/match_set/srs.rs:70; tools/ferrum2-rule-qualification/src/match_set/srs.rs:114.
The independently built synthetic reference returns BuildEvidence, which is discarded using underscore. The synthetic_srs measurement instead records binary_build.combined(wrapper_build). Its reported build time and compiled memory therefore describe binary decoding plus a snapshot wrapper, not independently constructed synthetic materialization. README states independent materialization correctness/build/compiled-memory evidence is retained. Pair timing intentionally uses the same compiled object, which is valid for the stated same-process parity scope; that choice does not require discarding independent build evidence.
Direction: keep explicit independent build evidence separate from shared-object timing materialization, or correct field semantics/schema/docs together. Verify construction provenance through small deterministic objects without latency runs. This is a measured-evidence attribution error; no speedup/regression magnitude is claimed.

### RTL-05 — P2 contract: ordinary workspace test gate executes benchmark workloads
Locations: tools/ferrum2-rule-qualification/src/route_program.rs:457; .github/workflows/m0.yml:150; match_set/tests.rs; dns_policy.rs tests.
Rust unit tests directly call benchmark/run_route_programs/run_dns_qname/run_generated_binary_srs. Scoped guidance permits only compile-only qualification gates during ordinary development, but the root ordinary cargo test --workspace exclusion list and m0 CI include this package. As written, the ordinary workspace gate executes timed qualification operations. Reading this call chain suffices to establish the workflow mismatch; the workloads were not executed here.
Direction: exclude this package's runtime tests from ordinary workspace execution and preserve --no-run, or place timing exercises behind an explicit qualification-only opt-in. Keep pure schema/fixture correctness tests independently runnable if needed. Update the root commands/workflow and owning docs atomically.

### RTL-06 — P2 contract: open-ended diagnostics bypass the qualification closed-error boundary
Locations: tools/ferrum2-rule-qualification/src/execute.rs:43; execute.rs write_report/runner_fingerprint/sha256_file; tools/performance_rule/runner_report.py:321.
Rust QualificationError stores arbitrary String, and IO errors are interpolated directly into operator output. Python run_once forwards the last 2,000 stderr characters of a failing runner, while main prints OSError/TimeoutExpired text. Scoped Rust guidance explicitly forbids injected errors and paths beyond its documented fingerprint; the tool boundary does not enforce that. Some interpolated product errors are closed, but raw IO/process failures are not.
Direction: use closed error categories and explicitly allowed stage/location fields. Retain raw failure bytes only in an explicitly authorized evidence channel if needed, not default stderr. Test redaction with ordinary injected exceptions, without process/network activity.

### RTL-07 — P2 lifecycle: producer aggregate output and consumer evidence size bounds disagree
Locations: tools/performance_rule/cli.py:81; tools/performance_rule/evidence.py:26; tools/performance_rule/runner_report.py:20.
Each runner stdout may occupy up to 64 MiB. cli retains twelve full reports and emits the aggregate without an encoded-size cap. The current evidence reader rejects any controller/calibration source above 64 MiB. A set of individually accepted runner reports can therefore produce an unreadable controller artifact and substantial aggregate in-memory duplication during JSON serialization. Existing bounded generated profiles may or may not reach this in normal use; no size workload was generated, so actual profile-specific overflow is unmeasured.
Direction: derive a coherent run-wide evidence budget and fail closed before expensive collection/serialization, or version the artifact into a bounded manifest plus individually hash-bound raw reports. Preserve exact stdout/file bytes and atomic replacement.

### RTL-08 — P2 usability: review-calibration can emit an artifact that cannot resolve its source
Locations: tools/performance_rule/evidence.py:275; tools/performance_rule/cli.py:265.
The review output stores only source_resolved.name, and load_calibration resolves it relative to the calibration artifact directory and requires the source to remain in that directory. CLI permits --output in a different directory and does not copy or validate placement of the source. The review command can return success while creating an artifact whose source is absent or resolves to unrelated bytes on later load.
Direction: validate output/source colocation before emitting, or explicitly materialize a hash-bound source bundle in the chosen output directory. Add a filesystem-only test for different source/output directories. No file movement was attempted here.

## Measurement/architecture observations and limitations

- Timing owner performs explicit warmup, self-calibration to at least 100 microseconds, retained actual operation counts and raw durations. MatchSet and operation pairs run 32 alternating rounds, balancing first position 16/16 within each retained sample. Samples alternate starting role by stable scenario hash. Iteration and sample bounds exist; maximum iteration count can terminate calibration below the minimum time, which the controller would reject. This is not proven reachable with the current clock/workloads.
- Allocation instrumentation has one global owner (tools/ferrum2-rule-qualification/src/measurement/allocation.rs:13); timing measurement regions and five one-op allocation regions are separated. The StatsAlloc global allocator still instruments allocations occurring during DNS latency work: separation avoids Region bookkeeping in timing but cannot remove the global allocator wrapper's overhead. README's statement that instrumentation cannot distort p50/p99 is stronger than the implementation supports. DNS rows openly include query/scratch construction; they are observations rather than allocation-free matcher gates.
- Allocation lock is test-only and shared by all read Rust tests. Production execute is public and has no exclusivity guard; the binary invokes it serially, so no ordinary concurrent contamination is demonstrated. Document single-threaded/exclusive measurement obligations or minimize public execution API before supporting embedded callers. Unrelated allocator activity in an embedding process would be included in global regions.
- Same-process 5% median/15% p99 MatchSet parity is explicitly separated from cross-version controller adoption policy. Route/DNS are retained as cross-process observations, not hard gates. The 10% outer ceiling belongs to Python policy; the Rust noisy_gate_ceiling value is exported metadata and unused in Rust parity decisions. No cross-version threshold was found applied inside Rust.
- Same-object MatchSet timing deliberately measures backend parity and scheduler noise, not wrapper lookup cost or independent layout. Route/DNS whole-program dispatch has its own paired rows. This limitation should accompany performance claims; current parity cannot prove semantic or performance equivalence for every matcher input.
- Real SRS files are named fixed fixtures, hashed and recorded, but run_real_srs reads them without a file-size cap and labels them pinned_repository_fixture without checking a reviewed expected hash. The trusted repository-fixture assumption must be made explicit or enforced. This audit did not replace fixtures.
- tools/ferrum2-rule-qualification/src/execute.rs:199: git_head/git_tree bind committed identities, while status_sha256 hashes porcelain path/status bytes rather than dirty file contents. Different edits to the same dirty paths yield the same status digest. Runner SHA still binds the executable. Do not interpret this status digest as a complete source-content identity; use a closed per-file source manifest when claiming reproducible dirty-source provenance. These packages do not themselves emit such a manifest, and external workflow/bundle owners were not exhaustively audited here.
- Current v6/v2-only controller/calibration acceptance, duplicate-key/nonfinite/depth/integer JSON limits, subprocess output caps, timeout, draining and atomic Python report replacement were read. Rust output uses direct fs::write (non-atomic) and print, so failure before stdout or a broken pipe can prevent complete evidence delivery; this is a recoverability design item rather than a demonstrated loss.
- Source modules are private with only Args/Profile/QualificationError/execute exported; internal helpers are often pub(crate) but remain inside explicit owners. report structs serialize in stable declaration order; JSON stdout/file encoding is shared per emitter. String suite/source/scenario vocabulary is still widespread; use closed types where it reduces evidence-contract drift, not a generic benchmark actor.
- Pairing builds rows_by_id anew for every scenario and pair, adding avoidable quadratic controller reduction work. This is outside measured timing and unprofiled; index each raw report once if controller latency becomes material.

## Verification and remaining work

This task was static-only. No benchmark, Rust test, Python test, compile gate, abnormal-input generation or dynamic reproduction ran. All production source in the two assigned packages was read; external archived evidence, complete test suite and CI/source bundle implementation were not exhaustive scope. Relevant test excerpts and m0 ordinary test invocation were inspected solely to trace contracts.

Root should merge these findings with the full-workspace audit before design/implementation. Evidence-consistency and workload-identity contracts must be settled before using the controller's result as proof of no regression. Follow with allowed compile-only qualification gates and mocked/offline controller tests; explicit paired performance collection and CPU profiling remain later phases.
